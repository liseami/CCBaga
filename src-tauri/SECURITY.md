# 原生安全边界

此地图覆盖原生进程识别、清理路径、浏览器启动、系统设置、安装与代理传输。仓库中的原生宿主没有遥测、账号资料上传、剪贴板读取、浏览记录采集或远程凭据提取服务。身份管理经用户主动确认读取默认 Claude 凭据到受保护的本机加密保险库；不发送给 WebView 或网络。第三方浏览器、访问网站、AI 服务和外部安装器的行为不属于这一实现边界。

## 状态与授权

- Linux 源码安装器检查整个本安装应用目录下的进程，A 或 B 运行时均拒绝替换其资源；回归验证安装目录保持不变。
- Linux 定位未知保持 `null`，不能显示已关闭或触发绿色通过；不可验证的机器对齐在任何系统修改前停止。
- 官方发布任务只允许 `liseami/CCBaga` 的所有者触发和重跑；PR 和 fork 不触及签名凭据。开发文档不授予官方发布身份。

## 发布与入口边界

- `skills/ccbaga-network/providers.json` 由固定导航编译内嵌，也供独立 Skill 消费，WebView 传供应商编号，不传可任意改写的 URL；现有回归锁住两条原始完整目标地址。
- Linux/Arch 构建任务没有 Apple 或更新私钥；macOS 临时钥匙串只授权 codesign。构建、DMG 工具和更新签名子进程不继承 Apple 凭据，公证工具只接收明确的认证参数。
- RPM 使用标准 rpmbuild 从已构建的非 AppImage /usr 文件树生成，禁用安装钩子和引擎剥离；Linux 内置更新仍禁用，RPM 当前沿用非 AppImage 宿主的 DEB 类型提示；后续启用 Linux 更新必须先补齐 RPM 类型标注。DEB/RPM/AppImage 将浏览器隔离在 libexec，避免 linuxdeploy 将可选 Qt 库当作宿主必需依赖或改写厂商 ELF；解包后仍严格比对引擎字节。所有平台产物验收完成后才创建正式版本。公开产物清单不包含密钥、钥匙串或完整私有配置。

## 本机开发与正式安装

本机 `dev:install` 不读取 Apple/更新私钥，强制临时签名与 debug/custom-protocol。开发浏览器临时签名清除 runtime，避免无 Team ID 的 Framework 被正式库验证拒绝；正式签名仍启用 runtime 与可信时间戳。安装前实际执行 Chromium --version 验证加载。开发安装只能选择仓库的 debug 宿主和本机引擎；拒绝与外部 DMG 路径组合，并核验两个包确为临时签名。正式安装仍要求严格签名和 Gatekeeper。此开发边界不移除下载包隔离、不禁用系统安全机制；用户数据仍沿用同一事务保护。

Windows Skill 私密文件采用用户 SID 独占且保护的 NTFS ACL，写入秘密之前核验；拒绝 junction 和 symlink 父目录。原生 OpenSSH/curl、不依赖 WSL；Job Object 只管理本次子进程树。Windows CLI 卸载和 NSIS 更新不删除用户配置/技能/资料；安装回归只在空白 CI runner 执行。Windows 构建不接触 Apple 凭据或更新私钥，版本签名仅在验收后的独立步骤注入。

## 验证边界

前端、原生、安装边界与独立 Skill 使用可重复的离线回归；公开更新向量另需实际清单与签名归档。Skill 回归使用临时生成密钥和伪配置，不使用用户凭据，不连接 VPS。配置非交互验证、拒绝 Git/Skill 写入与覆盖、秘密标准输入传输、完整目标链接、配对/权限/清理与失败/超时均有可运行回归。各平台构建运行 Skill 与原生验收，Linux 安装包按真实引擎字节检查后才交付。真实 VPS、家宽账号、TUN、桌面权限和第三方浏览器行为须在目标环境验证；未执行的操作不记为通过。视觉验收由项目所有者完成。

目录统计完整遍历白名单目标的元数据，不读取正文、不进入链接目标；不以目录规模或计时截断正常扫描。任何元数据或目录读取失败均显示路径和系统原因，并拒绝生成该目标的删除快照。清理前仍重复比较完整树指纹，变化即拒绝。

### 已确认的上游依赖风险

Linux 的 Tauri/Wry/GTK3 依赖链仍要求 `glib ^0.18`。原版 `glib 0.18.5` 命中 [RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html)，不能通过另加 `glib >=0.20` 替换旧 ABI。本项目以 `[patch.crates-io]` 指向 `vendor/glib`：它是 SHA-256 为 `233daaf6e83ae6a12a52055f568f9d7cf4671dabb78ff9560ab6da230ce00ee5` 的 crates.io 原包，仅应用[官方修复 b5a4071](https://github.com/gtk-rs/gtk-rs-core/commit/b5a4071e439bef2b5eea76c3aa25e5ae84839e34)的两行变更，把 C 出参改为 `let mut p` / `&mut p`。保留原版本、MIT 许可与上游源文件，不以改版本或扫描忽略伪装修复。

`python3 scripts/test-glib-backport.py` 逐文件核对原包摘要，只有上述已知回补允许偏离。Linux CI 另运行 `--native`，以真实 GLib 的优化构建执行上游 `variant_iter::tests`；完整应用仍经过 Ubuntu 22.04 原生检查。Cargo 的 registry 版本扫描不覆盖该本地路径依赖，因此 GLib 的来源验收与真实原生回归独立执行；后续新 GLib 公告仍须按受影响函数核对，不能把总体扫描零漏洞当作本地回补的自动背书。框架兼容官方安全版本后，应移除本地覆盖与对应快照。测试和审计各自报告实际结果，不将来源校验当成原生运行通过。

本轮完整 Cargo 锁扫描还更新了 `rustls 0.23.46`、`rustls-webpki 0.103.16`、`webpki-root-certs 1.0.10`、前后端 `tauri-plugin-updater 2.14.1`、`zip 9.1.3` 与 `zstd 0.14.3`，处理 TLS 秘密输出/握手/证书信任、ZIP 解包与压缩流复用公告。ZIP 按官方实际修复范围选用安全版本，不仅依赖公告数据库较宽的版本判断。2026-10-27 的官方 RustSec 数据库提交 `99670cfc0bc574433034b75876a4b791ccaa2efb` 扫描此锁文件为 0 条漏洞；Vite 7.3.7 后的 Bun 扫描同样为 0。该结果只针对当时数据库和当前锁定源码，不是未来不会出现漏洞的保证。

同一既有 GTK 构建链的 `proc-macro-error 1.0.4` 命中 [RUSTSEC-2024-0370](https://rustsec.org/advisories/RUSTSEC-2024-0370.html) 的停止维护提示；另有 `zbus_names 4.3.4`、`zvariant 5.15.0` 和 `zvariant_derive 5.15.0` 的停止维护提示。它们是维护风险，不应冒充已确认的运行时漏洞或恶意代码。依赖扫描无新增公告不等于整库没有风险，功能测试通过也不替代安全审查。

## 第三方浏览器补丁覆盖未验证

固定 Fingerprint Chromium `148.0.7778.215` 的 SHA-256 验收仅证明来源字节一致，不能证明 Chromium 安全补丁齐全。[Google Chrome CNA 的 CVE-2026-10881 原始记录](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/10xxx/CVE-2026-10881.json) 将 Chrome `<149.0.7827.53` 列为 ANGLE 越界读写/潜在沙箱逃逸的受影响范围；固定引擎的 Chrome 基线落在该范围。尚未取得该 Fingerprint 二进制与具体修复提交的可复现映射，因此本审计将其标记为“fork 回补覆盖未验证”，不直接断言 fork 已修复或未修复。

2026-10-27 核对[上游实际最新发行资产](https://github.com/adryfish/fingerprint-chromium/releases/latest)：`150.0.7871.186` 提供 Windows/Linux 资产，未提供对应 macOS 资产；上游还说明该版补丁源码延迟公开。没有可直接认定为已完成三平台兼容与安全验收的替换输入。本轮没有下载未经同等核验的新引擎，也没有关闭沙箱、TLS 或平台保护来绕过差异。后续替换必须核对实际源码/补丁、三个平台的完整 A+B 功能和安装/更新边界；应用依赖扫描零漏洞不代表这个第三方浏览器已经通过独立漏洞审计。

## 本地身份保险库

- 身份卡片按用户要求显示本地账号的用户名、邮箱和组织；从默认 .claude.json 的 oauthAccount 允许字段读取显示信息，并只提取默认凭据/settings 中有界的订阅与期限元数据，限制大小和显示长度，未知字段不序列化。Desktop 检测不读取 Cookie 值或钥匙串，不联网识别；Linux 仅查询已知登录 Cookie 名称的存在性和有界 OAuth 配置字段，读取失败显示不可读而非空身份。没有读取到显示信息时明确标注，不把缓存账号信息当成服务端认证结果。

- SQLite 只管理脱敏目录、保留选择和持久恢复状态；大文件和凭据写入 BAGAID01 认证加密容器。账号索引用本机密钥的 HMAC-SHA256，仅存摘要，不送 UI；按 UUID/组织匹配，缺失时用邮箱/组织，未知账号不合并。压缩使用 tar/Zstandard（旧 gzip 兼容），加密使用 ring AES-256-GCM；不是自创密码算法。
- 已有账号暂存先写入全新归档代次，完整认证验收后同事务提交目录指针与恢复标记；提交后才回收旧代次。恢复检查点不覆盖正常槽位。文件循环保留所有权/链接检查，进程按 250ms 间隔与事务关键阶段核验，停止进程不再触发无关全量扫描。
- 会话历史、附件、快照、日志和 Desktop 登录存储可能远大于凭据；压缩不能保证图片/数据库缩小到固定体积。保留选项不被速度优化隐式更改，项目源码不纳入。
- key.bin 与数据库/归档均在受限保险库中，POSIX 私有权限、Windows 当前用户独占 DACL；主密钥未放在 SQLite、安装包或公开仓库。本机同用户或管理员拥有的权限无法被文件格式消除，不能承诺 Claude 永远无法发现保险库。
- 默认 Code/Desktop 登录凭据经用户确认读取，macOS保留系统授权；原生调用无凭据 argv/网络传输。其他自定义配置目录的账号不自动切换。
- 正常刷新只读取目录与本地元数据，不打开 Store 或解密归档列表；缺摘要保持未知。凭据徽章只表示本地期限，缺失/旧数据未知，不承诺服务端有效或自动续期。进程预览最多 32 项真实名称/PID，失败为 null，不读取可能复用 PID 的旧会话工作区文件。停止/保存/切换不隐式删除锁；确认的普通瞬态锁/空锁目录不进入新快照或旧归档恢复，非空同名目录按保留策略处理。
- 原地备份只提交档案/名称/摘要事务，不改工作区、active/browser 指针或启动参数，UI 分开列出备份与工作区留存范围。
- 登录资料始终随身份暂存；用户控制其他数据的保留/暂存。只管理本地状态，服务端失效可能要求重新登录。程序卸载/重装保留保险库。
- 原有任意目录批量清理 RPC 已移除。身份切换始终先保存并验证归档；独立直接删除和默认文件残留清理由 GUI 明确确认，不新增备份，只处理所选范围。残留扫描对非空/内容未知的固定锁路径仅警告保留，不产生删除快照；空锁扫描后新增内容会在执行前拒绝。残留扫描不读取钥匙串；文件凭据仅清除 `claudeAiOauth` / `trustedDeviceToken`，保留 MCP/插件秘密。删除暂存卡片不修改当前工作区。文件删除不等于磁盘安全擦除。

## 显式密码迁移

保存卡片的导出/导入只通过 Rust 原生文件选择取得五分钟一次性路径票据；WebView 不接受任意路径、没有通用 dialog/fs 权限。密码只用于当前调用、不写日志或持久化。BAGAP001 以随机 32 字节 salt、固定 600000 次 PBKDF2-HMAC-SHA256 派生迁移密钥，复用 AES-GCM/tar/Zstd；不导出 key.bin、SQLite 或恢复日志。归档包含用户已保存范围内的登录材料，确认页要求保管文件和密码。

导入先完整认证并校验版本、同 OS、白名单路径、成员类型/重复、8 GiB/100000 成员上限；拒绝链接和 Windows ADS/设备名/大小写别名，不以 tar 结束代替加密认证结尾。以目标 home 重定位源元数据、目标主密钥重封装并重算账号 HMAC；新档案/摘要/可选指纹绑定同事务提交。重复账号/种子冲突拒绝覆盖。不会自动切换身份、修改当前工作区、启动浏览器或读取系统钥匙串。失败清理本次临时档案，不回收已有保险库文件。可选浏览器仅种子/环境设置，不含代理、Cookie、网页登录/密码或操作系统密钥；历史正文与项目绝对路径不改写，不承诺免重新登录；macOS 跨本地用户名迁移保留原 Keychain account、不猜 home 或重写 ACL，目标官方 CLI 按不同有效用户名查找时可能需要重新登录；Windows Desktop 的 DPAPI 等机器绑定资料未重包为目标机器密钥，文件导入成功不代表登录已恢复。

迁移导入本身不执行归档配置、不启动 Claude/浏览器。归档可含用户选择的 hooks、插件、MCP 等；完整性与路径验收不是代码净化或来源认证，GUI 必须明确确认来源可信，后续恢复并启动第三方客户端可能执行配置命令。

## 可选浏览器联动

未设置用户默认启用且保留显式关闭；初始资料原地保留，在显式切换/联动确认时建立绑定，原地保存备份不改变当前绑定。SQLite v3 仅增加本软件身份 ID、资料槽位和派生种子的绑定，不读取浏览器 Cookie 正文。身份选择与资料指针同事务提交，失败回滚；崩溃恢复期间阻断 B 启动，Mac 无启动参数时不回退。正常退出后才切换，重开失败单独报告。每身份独立 user-data-dir/配置，后续身份使用独立资料并保留旧资料；重新启用时可选择采用原资料。浏览器资料不进入加密身份包，依赖 Chromium/OS 本身的保护，不宣称同用户隔离、匿名、跨客户端账号一致或第三方零外连。删除关联资料有独立选项、范围校验和使用中拒绝；实际网页登录须由用户完成。本机/CI 使用临时真实浏览器资料证明 Cookie 与站点存储隔离，不读取真实钥匙串或浏览器数据。
